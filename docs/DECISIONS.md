## 2026-11-04 (v1.2): audit clarification: analytic quantities from the stated input distribution

- **Rule (all audits):** computing a quantity analytically from the spec's stated input distribution, with no labels and no sampled examples, counts as writing, not fitting. Example: parity_hidden `claude-opus-5-5__claudecode-noexec__finetune_family/sample_01` sets b2 from the average of its own output over the 17 possible counts of ones under uniform bits (binomial weights, no labels). Added to audit-init check 3.
- **Reason:** that sample was approved under this reading in the 2026-11-04 batch audit. This entry makes the reading explicit, so later audits apply it the same way.

## 2026-11-04 (v0.11): analysis-only: ceiling status and per-sample table

- **Ceiling status** in `scripts/analyze.py`: when an arm's and the random arm's mean test accuracy at the same budget are both >= 0.995, the cell reports "both at ceiling" instead of a multiplier (status `ceiling` in multipliers.csv). Reason: with both arms saturated, the interpolated multiplier (e.g. sparse_parity 1.00x / 0.25x at n = 1024 / 4096) only reflects where random's curve first hits 1.0, not a data saving. No change to training, configs, `metrics.resolve`, or any other cell.
- **Per-sample table** (report.md, per_sample.csv): mean test accuracy by written sample_id and budget, plus mean test loss at every budget (gridnav's three samples all score 1.000 zero-shot; loss separates them), so sample differences are not averaged away. Samples are assigned seeds round-robin (1-2 seeds each), so fine-tuned differences between samples also include training-set variation.
- **Re-analyzed:** results/main_v1 (runs.jsonl unchanged). 8 cells changed to ceiling, all sparse_parity at n = 1024 and 4096 (opus, opus_noise, opus_norm_matched, opus_shuffled_noise).

## 2026-11-04 (v0.10): memorization check required for digits8x8 audits

- **Found by the audit of** inits/digits8x8/claude-opus-5-5__claudecode-noexec/sample_00 (now rejected_00): its NOTES.md named `load_digits`, and 9 of its 23 prototypes are real load_digits images of 0 to 8, recalled from memory (distance 0.13 to 0.22, 59 to 64 of 64 pixels equal on the 0-9 grid; one, index 6, is in the test split). The fence held: the agent saw no data, it recalled it. Rejected under audit check 3, because those weights are set from real labeled examples. Reading build.py could not catch this; only comparing against the real images could.
- **Rule** (audit-init check 7): every digits8x8 audit must run `uv run python -B scripts/memcheck_digits.py <sample_dir>`. It compares each prototype recovered from build.py (`--protos EXPR` for layouts other than rejected_00's) and each W0 column (rescaled to [0, 1], both signs) with all 1,797 real images, also shifted by up to 1 pixel in each direction. A candidate closer to a real image than the dataset's minimum same-class nearest-neighbour distance (0.33 on `data / 16`) means REJECT, and the script exits 1. No two real images of one class are that close, so a candidate that close is a copy, not a drawing. Zero-shot accuracy, near-duplicates below the 1st percentile (0.58) and class-mean correlations are printed for context; only the floor decides.
- **Auditor-side only:** the script reads the real dataset, so its output never goes into a prompt, retry message or workspace (integrity rule 1). Test: `tests/test_memcheck.py` (a 1-pixel-shifted copy is found only with shifts; a negated, scaled, shifted real image in a W0 column exits 1; a gaussian blob exits 0).
- **Limits:** a template blended from several real images, shifted by 2 or more pixels, or transformed in a way `--protos` doesn't undo is not detected.
- **Samples:** rejected_00 fails the rule with the script (9 prototypes at 0.13 to 0.22, exit 1). sample_02 was audited under it (closest template 1.00, W0 column 1.09, exit 0). sample_01 was approved earlier with the scratchpad version, which had no shift check; rerun with the script on 2026-11-04 it exits 0 (closest raw template 1.02; closest blurred template and W0 column 0.80, a generic "1"), so its approval stands.
- **Not decided here:** the digits8x8 task spec names `load_digits`, which may invite recall. Whether to change the spec or prompt before regenerating is a separate decision.

## 2026-11-03 (v0.3): fairer controls, no multipliers from noise

Approved by Garrett after the v0.2 smoke run (results/smoke_20261103_195350/).

- **Problem 1:** plain `shuffled` on sparse_parity never learned (0.507 at 1,024 examples vs 0.995 for random). Cause, measured on the reference init: shuffling mostly-zero weights leaves 22-27% of layer-1 and 0-6% of layer-2 ReLU units ever active. A unit with zero input weights and non-positive bias sits where the ReLU gradient is 0 and never updates. Real agent inits are likely just as sparse, so "written beats shuffled" would be too easy.
- **Fix 1:** new `shuffled_noise` arm (shuffle, then the same 0.1x noise as written_noise; 94% / 97-100% of units alive) is the primary structure control, compared against `written_noise`. New `norm_matched` arm (random directions, written per-tensor Frobenius norms) is the scale control, compared against `written`. Plain `shuffled` stays as a secondary check. H3 restated accordingly. In the v0.3 smoke run the secondary comparison credited structure with +0.493 at 1,024 examples; the paired written_noise - shuffled_noise comparison gave +0.104.
- **Problem 2:** interpolating against random's flat, at-chance stretch on sparse_parity (0.499, 0.491, 0.504 for budgets 0-128) produced numbers like "worth ~109 examples" for an arm at chance.
- **Fix 2:** `metrics.resolve` withholds the multiplier when the arm is within max(0.02, its CI half-width) of a majority-class predictor, reports only an interval when the bracketing random segment rises less than max(0.02, random CI half-widths), and always reports the interpolation bracket with point estimates. Each job now records the majority-class test accuracy.
- **Added:** `comparisons.csv` and a Controls table in report.md with paired-by-seed differences.
- **Cost:** two more arms in default.yaml, about 1.5x sweep time.

## 2026-11-03: initial design (starter kit)

- **Plain numpy instead of PyTorch.** Networks are 1k-15k parameters; numpy keeps backprop transparent and testable (finite-difference checks), needs no GPU, and matches the numpy format the LLM writes. Revisit if networks grow past roughly 1M parameters or need GPUs.
- **Supervised tasks only (including behavior cloning for gridnav).** Removes RL variance so the comparison isolates initialization.
- **Disjoint data partitions** for finite input spaces (sparse_parity, gridnav, digits): test/val/train never share an input.
- **Paired, nested training sets.** For seed s, every arm trains on the same examples, and the budget-n set is the first n of one fixed pool. Reduces variance in arm differences.
- **Fixed validation set (256 examples; 200 for digits) for all budgets and arms.** Fair across arms, but it means total labeled data used exceeds the nominal budget, especially at n = 16. Report this. Possible follow-up: validation size proportional to budget.
- **Step 0 is an eligible early-stopping checkpoint.** If fine-tuning only hurts a written init, validation can choose "no training". Reported as "step-0 selected".
- **Selection by validation accuracy, ties broken by validation loss.**
- **Retries carry only format or rule errors**, max 2 per sample (v0.2: max 1, as fresh agent sessions).
- **Shuffled control** (permute entries within each tensor) separates structure from weight scale.
- **Shuffled control caveat:** because written weights are mostly zeros, shuffled nets can have many dead units and train worse than random. It is a structure-vs-scale check, not a neutral baseline. Each sample's zero fraction is stored in meta.json.
- **written_noise arm** (alpha = 0.1 x He std) tests whether dead or unused units in written inits limit fine-tuning.
- **Reference inits** for sparse_parity, ring2d and gridnav were written by Claude in chat to the same rules, solely to test the pipeline. They are not a human baseline.
